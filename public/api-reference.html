Code Lab API Reference

Every desk's Code Lab exposes a function you write to control the bot. Each function receives a context object ctx with market data and returns a trading signal. This reference covers every function signature, all available context properties, and valid return values.

How Code Lab Works

In Code Lab mode you write a pure JavaScript function. The engine calls it on every bar/tick with fresh market data. Your function reads ctx and returns an action. The engine handles execution, P&L tracking, and the live chart — you focus purely on the logic.

// Pattern for every Code Lab function
function yourFunction(ctx) {
  // Read market data from ctx
  // Apply your logic
  return 'SIGNAL'; // or { key: value }
}

Functions are compiled with new Function() — standard JS only, no imports or external calls. You have access to all built-in JS math functions.

⚖️ Spread Trader

📍 spread-trader.html › Code Lab tab

Pairs trading across 5 co-integrated pairs generated with an Ornstein-Uhlenbeck process. Your signal(ctx) decides when to go long/short/flat the spread.

Function signature

function signal(ctx) {
  // Your logic here
  return 'LONG_SPREAD';
}

ctx properties

PropertyTypeDescription
ctx.zscorenumberZ-score of the spread over last 30 bars. Positive = spread above mean.
ctx.spreadnumberRaw spread value (priceA − β × priceB)
ctx.priceAnumberCurrent price of the first leg
ctx.priceBnumberCurrent price of the second leg
ctx.posnumberCurrent position: 1=LONG_SPREAD, -1=SHORT_SPREAD, 0=FLAT
ctx.barnumberCurrent bar index (0–299)
ctx.betanumberHedge ratio β for the pair
ctx.pairAstringTicker of leg A (e.g. "SPX")
ctx.pairBstringTicker of leg B (e.g. "NDX")

Return values

'LONG_SPREAD' | 'SHORT_SPREAD' | 'FLAT' | 'HOLD'

'LONG_SPREAD' — buy A, sell β×B (bet spread rises back to mean). 'SHORT_SPREAD' — sell A, buy β×B. 'FLAT' — close position. 'HOLD' — do nothing.

🌐 Regime Rider

📍 regime-rider.html › Code Lab tab

Macro allocation strategy. Your allocate(ctx) is called for all 4 macro regimes. Return portfolio weights for each instrument.

function allocate(ctx) {
  var weights = {};
  if(ctx.regime === 'RISKOFF') {
    weights.GOLD = 40; weights.TLT = 40; weights.GLD = 20;
  } else {
    ctx.instruments.forEach(k => weights[k] = 100/ctx.instruments.length);
  }
  return weights;
}
PropertyTypeDescription
ctx.regimestring'GROWTH' | 'INFLATION' | 'RISKOFF' | 'DEFLATION'
ctx.instrumentsstring[]Array of available instrument keys for this scenario
ctx.expected_returnsobject{key: expectedReturn%} — regime-specific expected returns by asset class
ctx.driftMultobject{key: multiplier} — drift multiplier per instrument (higher = stronger regime tailwind)
ctx.optimalWeightsobjectReference optimal weights (you can peek, but try to figure it out!)
{ instrumentKey: weight, ... }

Weights are automatically normalised to sum to 100. Regime fit score is based on how close your weights are to the optimal for that macro environment.

function strategy(ctx) {
  var r = ctx.rsi(14);
  if(ctx.position === 0) {
    if(r < 30) return {action:'buy',  qty:50};
    if(r > 70) return {action:'sell', qty:50};

  if(ctx.position > 0 && r > 55) return {action:'sell', qty:50};

📣 Options Outcry

📍 options-outcry.html › Code Lab button on setup screen

Delta hedging simulation. You hold a call option on an underlying with GBM + vol regime switching. Your hedge(ctx) decides how many shares of stock to buy/sell to neutralise delta exposure.

function hedge(ctx) {
  const THRESHOLD = 0.05;
  const deltaError = ctx.delta; // net delta of options + stock hedge
  if(Math.abs(deltaError) > THRESHOLD) {
    return { stock_delta: -deltaError }; // neutralise
  }
  return { stock_delta: 0 };
}
PropertyTypeDescription
ctx.spotnumberCurrent underlying price
ctx.deltanumberPortfolio net delta (option Δ + stock hedge)
ctx.gammanumberPortfolio gamma (Δ acceleration)
ctx.veganumberPortfolio vega (vol sensitivity per 1%)
ctx.thetanumberPortfolio daily theta (time decay in $)
ctx.ivnumberImplied volatility (annualised, e.g. 0.25 = 25%)
ctx.barnumberBar index (0–199)
ctx.stock_posnumberCurrent stock hedge position (shares)
{ stock_delta: number }

P&L = gamma PnL (from spot moves) + theta (time decay) − transaction costs. Minimise residual delta to maximise Sharpe.

🔗 Arbitrage Sprint

📍 arbitrage-sprint.html › Code Lab button on setup screen

Automate Round 5 (live order book market making). Your captureArb(ctx) decides whether to buy or sell each tick in a 2-minute order book simulation.

function captureArb(ctx) {
  if(ctx.spread > 5) {
    return ctx.inventory > 0 ? 'SELL' : 'BUY';
  }
  return 'HOLD';
}
PropertyTypeDescription
ctx.midnumberCurrent mid price
ctx.bidnumberBest bid in order book
ctx.asknumberBest ask in order book
ctx.spreadnumberBid-ask spread in basis points
ctx.inventorynumberCurrent net inventory (shares)
ctx.pnlnumberCumulative realised P&L
ctx.ticknumberCurrent tick index (0–119)
ctx.momentumnumber10-tick price momentum (fractional return)
'BUY' | 'SELL' | 'HOLD'

Score = max(0, 50 + PnL/2 − |inventory|×3). Minimise residual inventory at session end.

💡 Tips for all Code Labs

• Functions are pure JS — use standard math, arrays, and closures freely.
• No await, fetch, or DOM manipulation inside functions.
• The engine calls your function every bar/tick with a fresh copy of ctx.
• Return values not matching the expected format are treated as HOLD/no-op.
• Errors inside your function are caught silently — the bar is treated as HOLD. Check the console for runtime errors.
• XP is awarded at session end — better performance = higher XP.
